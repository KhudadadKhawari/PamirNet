# AWKH Rollout Runbook

This is the first production migration from Janitor RADIUS to PamirNet.

## Current legacy AAA reference

AWKH currently uses Janitor/FreeRADIUS at `10.250.250.1`, reached through the existing L2TP management tunnel. MikroTik uses RADIUS for both Hotspot and PPP, accounting is enabled, and incoming RADIUS disconnect/CoA uses UDP 3799.

PamirNet v1 is central-VPS AAA. PamirNet Edge/offline authentication is not part of this rollout; if the VPS/WireGuard path is unavailable, new authentications can fail.

## Rollout rule

Do not remove Janitor configuration during initial cutover. Keep it available as a disabled rollback path until PamirNet has been stable for at least 72 hours.

## Stage 1 — Inventory and backup

On the AWKH MikroTik before changes:

```routeros
/export hide-sensitive file=before-pamirnet
/radius export hide-sensitive
/ppp aaa print detail
/ip hotspot profile print detail
/radius incoming print
/interface l2tp-client print detail
/ip route print detail where dst-address=10.250.250.0/24
```

Download the RouterOS export and keep it with the maintenance record.

Record:

- current active PPP sessions
- current active Hotspot sessions
- Janitor subscriber count
- package/speed definitions
- disabled/expired subscribers
- vouchers that must remain usable
- current RADIUS request/timeout counters

## Stage 2 — Deploy PamirNet VPS

Follow `docs/production-deployment.md`.

Verify before touching production AAA:

```bash
curl -fsS https://<pamirnet-domain>/api/ready/
sudo wg show
docker compose --env-file .env.production -f docker-compose.prod.yml ps
```

## Stage 3 — Register AWKH router

Create the AWKH tenant and register the main MikroTik through PamirNet Networking.

Use the generated WireGuard/MikroTik configuration. Confirm:

- router status becomes Online
- latency/packet loss is visible
- RouterOS API works only through WireGuard
- PamirNet FreeRADIUS client contains the router tunnel IP

From the VPS:

```bash
sudo wg show
sudo tcpdump -ni wg0 'udp port 1812 or udp port 1813 or udp port 3799'
```

## Stage 4 — Normalize Janitor data

Export/prepare a normalized subscriber CSV with these columns:

```text
username,name,password,phone,address,notes,status,package,started_at,expires_at,mac_address,mac_lock_mode
```

Valid statuses:

```text
active
disabled
expired
suspended
quota_exhausted
```

Map Janitor `Disabled` and `Expired` state-pool users to PamirNet subscriber states rather than reproducing the legacy `10.254.0.0/24` and `10.255.0.0/24` behavior.

Create PamirNet packages first, then dry-run import:

```bash
docker compose --env-file .env.production -f docker-compose.prod.yml exec backend \
  python manage.py import_subscribers_csv \
  --tenant awkh \
  --file /migration/awkh-subscribers.csv \
  --dry-run
```

For the actual import, mount/copy the CSV into the backend container or run the management command from a temporary container with a read-only bind mount.

If legacy plaintext passwords are unavailable, generated credentials require an explicit protected output file and customers will need the new credentials.

## Stage 5 — Test identities before cutover

Create/import dedicated test identities:

- one PPPoE subscriber
- one Hotspot subscriber
- one voucher
- one throttled/FUP test package

Validate:

1. Access-Accept
2. correct MikroTik rate limit
3. Start accounting
4. Interim-Update accounting
5. Stop accounting
6. online session visibility
7. Disconnect request
8. package change/CoA
9. expired/disabled rejection
10. voucher first-login activation

Do not proceed if accounting or disconnect/CoA is unreliable.

## Stage 6 — Prepare RouterOS rollback pair

Keep the Janitor `/radius` entry intact but disabled during PamirNet production operation. Add PamirNet using the generated tenant/router secret.

Conceptually:

```routeros
/radius add address=<PAMIRNET_WG_IP> secret=<PAMIRNET_SECRET> service=ppp,hotspot authentication-port=1812 accounting-port=1813 comment="PamirNet"
/radius incoming set accept=yes port=3799
```

Restrict firewall access so RADIUS/CoA is allowed only over the WireGuard path.

Do not paste example secrets/IPs literally; use the values generated by PamirNet.

## Stage 7 — Cutover

Schedule a short maintenance window.

Immediately before cutover:

```bash
bash scripts/backup-production.sh
```

Then on MikroTik:

1. disable the Janitor RADIUS entry
2. enable PamirNet RADIUS
3. leave existing customer sessions running initially
4. authenticate test PPPoE + Hotspot clients
5. confirm accounting appears in PamirNet

Watch for 15–30 minutes:

```routeros
/radius monitor [find comment="PamirNet"]
/ppp active print count-only
/ip hotspot active print count-only
```

On VPS:

```bash
docker compose --env-file .env.production -f docker-compose.prod.yml logs -f --tail=100 freeradius backend celery
```

## Immediate rollback

Rollback trigger examples:

- repeated RADIUS timeouts
- widespread Access-Reject for valid imported users
- accounting not arriving
- PPP/Hotspot session establishment failing
- unexpected rate-limit behavior

Rollback:

1. disable PamirNet RADIUS entry on MikroTik
2. re-enable Janitor RADIUS entry
3. verify new PPP/Hotspot login through Janitor
4. do not delete PamirNet data; preserve it for diagnosis

Existing PamirNet-authenticated sessions may remain online until disconnected/re-authenticated.

## Stage 8 — Post-cutover validation

During first 72 hours compare:

- active session count vs expected AWKH baseline
- total hourly traffic
- RADIUS rejects/timeouts
- subscriber expiration behavior
- voucher activations
- CoA/disconnect success
- router latency/packet loss
- database backup success

Run at least one restore verification:

```bash
bash scripts/restore-production.sh /var/backups/pamirnet/<backup>.dump --verify-only
```

## Stage 9 — Retire Janitor path

Only after stable operation and confirmed backups:

- retain a final Janitor export/database backup
- remove/disable the Janitor L2TP dependency when no longer needed
- remove the static `10.250.250.0/24` route if it exists only for Janitor
- keep the old RADIUS configuration documented for rollback history

Do not change unrelated AWKH LAN/Hotspot/PPPoE topology during the AAA migration window.
